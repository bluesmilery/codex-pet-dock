# Eighth break-loop: private implementation boundary

## 1. Trigger and stop decision

- Campaign: v8 second formal Review of `<v8-r2-base>`.
- Result: P0=0, P1=1, P2=1. Per workflow, v8 stops without QA; no third patch or Review is allowed.
- Scope: evidence-sink privacy and build-flag verification only. The original full-hide branch is still unsampled and unresolved.

## 2. Findings and root cause

### 2.1 P1: declaration inventory is still syntax enumeration

W7 claimed to pin every declaration-shaped line outside the test region, but its pattern did not recognize legal Swift forms such as `convenience init` or `static subscript`. An isolated mutation proved both forms compiled in release and left all privacy tests green; an external production file could then use the new convenience initializer to select an arbitrary sink.

This is not a missing pair of keywords. `required`, `lazy`, `mutating`, multiple attributes and future grammar forms create the same class of escape. The r1 repair violated the seventh break-loop decision by rebuilding a declaration parser with a regular expression. Root category: **wrong enforcement layer + recurrence of a prohibited repair paradigm**.

### 2.2 P2: compiler flags were treated as substrings, not tokens

W5 counted only joined `-DPETDOCK_TESTING`. Swiftc also accepts separated `-D PETDOCK_TESTING`; an isolated Makefile mutation placed that form in another recipe while W5 stayed green. Root category: **incomplete command grammar model**. Unlike Swift source syntax, this finite surface is correctly handled by shell tokenization.

### 2.3 Why the workflow did not prevent recurrence

The seventh plan correctly said declaration shape was only an accidental-drift canary and warned that definition-file APIs remained a residual Review responsibility. After r1 found a String-derived sink, the repair batch promoted that canary into a full declaration inventory instead of returning to the structural residual risk. Main admission checked the documented MA11 cases but did not compare the new W7 paradigm against the prior break-loop prohibition. Prevention therefore needs an admission question: **did a Review repair reintroduce a defense class already rejected by the controlling break-loop?** If yes, reject before second Review.

## 3. v9 structural contract

1. Add an internal `RuntimeEvidenceRecording` capability protocol containing only the existing record, snapshot and flush operations required by production consumers.
2. Make the sink-owning `RuntimeEvidenceCollector` itself `private final`. Its URL, initializer and every possible member remain invisible to all other files regardless of declaration spelling.
3. Expose the exact same-file production facade `makeRuntimeEvidenceRecorder(candidateSHA:flushNow:) -> any RuntimeEvidenceRecording`. Its signature accepts candidate SHA and monotonic clock only; the sink remains fixed to the private Diagnostics evidence file.
4. Keep the exact test-only facade `makeRuntimeEvidenceRecorderForTesting(candidateSHA:outputURL:flushNow:) -> any RuntimeEvidenceRecording` inside `#if PETDOCK_TESTING`. A fixture filename constant may be internal, but no URL/path capability may leave the private implementation.
5. Production consumers store/pass the protocol existential, never the concrete type. No URL or write capability enters the protocol.
6. Delete old W0, W3, W6 and W7 rather than adapting them: private-init shape, URL token allowlist, static-production shape and declaration inventory are superseded. Retain/update only the test-facade token/region and Package absence guards, add external compilation probes, and never reintroduce a Swift declaration or constructor inventory.
7. Tokenize every Makefile swiftc command. Count both `-DNAME` and `-D NAME`, reject a dangling `-D`, and require exactly one `PETDOCK_TESTING` definition in the test-ui recipe. Package.swift must remain free of the flag.

This is stronger than v8 for the reported P1: adding `convenience init`, `static subscript`, `lazy var` or any other member to the private concrete type cannot make that member nameable from main or another production file.
