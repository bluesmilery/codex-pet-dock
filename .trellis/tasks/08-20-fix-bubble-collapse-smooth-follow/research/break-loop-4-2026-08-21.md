# Bug Analysis: Review evidence stopped before the production boundary

- Date: 2026-08-21
- Closed campaign: `0e6439b` -> `24b9732`
- Final Review result: P0=0, P1=0, P2=2; QA did not start.

### 1. Root Cause Category

- **Category**: D - Test Coverage Gap, with B - Cross-Layer Contract
- **Specific Cause**: Both remaining tests named the required scenario but did not make the required input travel through the production consumer and observable sink. The wall-clock fixture mutated a local value that scheduler/probe never read. The authoritative `targetMissing` fixture manually recomputed `Geometry.safeDockFrame`, bypassing `onVisibilityChange`, scheduler coalescing, and the real `DockPanel.frame` sink.

### 2. Why Fixes Failed

1. Initial typed-outcome implementation: it proved classification and helper geometry, but the full-hide red test stopped before the event-driven production composition.
2. First Review repair batch: it added a wall-jump variable and compared outputs, but did not first map `perturbation -> production consumer -> observable`; the test therefore could not fail if production reintroduced wall time.
3. Review-readiness mapping: acceptance criteria were mapped to test names and passing counts rather than to the dependency edges each test actually exercised.

### 4. Systematic Expansion

- **Similar Issues**: callback-driven visibility changes, TCC transitions, display-link recovery, and retry-deadline tests can all pass while bypassing their scheduler or sink.
- **Design Improvement**: keep production clock input monotonic-only; make the absence of wall-clock APIs executable evidence instead of carrying a second unused clock through production.
- **Process Improvement**: integration test names must state source event, transport/coalescer, and final owner-observable state.
