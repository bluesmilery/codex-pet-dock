# Bug Analysis: Full message hide preserves a stale dock avoidance offset

## Bayesian update

| Hypothesis | Prior | Discriminating evidence | Posterior |
|---|---:|---|---:|
| H1: optional capture result conflates target-missing with capture-unavailable | 40% | Pixel collapse works; complete hide keeps the same avoidance gap while the dock still follows the pet; current capture boundary returns `nil` for all missing/failure paths and classifies nil conservatively visible | 75% |
| H2: obstacle geometry still admits a different invisible control/wrapper | 35% | A small residual helper window is visually present, but existing geometry excludes very small controls; exact candidate fixture is not yet captured | 18% |
| H3: scheduler or frame sink fails to run after complete hide | 25% | The dock changes absolute position with the pet while preserving the gap, which is unlikely if the frame were simply stale | 7% |

Confidence is below 90%, so implementation must begin with a discriminating typed-outcome red test. Do not change production classification or geometry if that test does not reproduce the stale obstacle.

## 1. Root Cause Category

- **Category**: B - Cross-Layer Contract; D - Test Coverage Gap; E - Implicit Assumption.
- **Specific Cause**: the CG candidate lifecycle and ScreenCaptureKit observation lifecycle are separate sources, but `BubbleCapturer` collapses authoritative target absence and generic observation failure into one optional `nil`. The downstream conservative rule is correct for failure but wrong for a target proven absent from a successful SCK snapshot.

## 2. Why Prior Fixes Failed

1. **knownWids invalidation**: covered the case where the WID disappears from the CG candidate set, but not the observed case where CG geometry lingers while SCK no longer contains the target.
2. **visible→hidden pixel test**: covered an existing shareable window whose alpha statistics collapse, but not complete UI teardown.
3. **scheduler wake and full layout harness**: proved a hidden result reaches the frame sink, but did not prove the capture boundary can produce hidden for authoritative target disappearance.
4. **automatic QA**: correctly left real-device behavior pending; the first exact-candidate manual run supplied the missing state transition and invalidated acceptance.

## 4. Systematic Expansion

- **Similar Issues**: any optional result combining “not found” with transport/permission/parse failure can make conservative fallback preserve stale state.
- **Design Improvement**: carry only policy-relevant provenance across the capture boundary; do not expose raw ScreenCaptureKit objects or add a general error framework.
- **Process Improvement**: acceptance matrices for lifecycle UI must separate content collapse, window disappearance, source-list disappearance, and source failure.
