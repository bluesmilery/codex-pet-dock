# Bug Analysis: Bubble cadence mixes monotonic and wall clocks

## Bayesian update

| Hypothesis | Prior | Discriminating evidence | Posterior |
|---|---:|---|---:|
| H1: incompatible clock domains cross the scheduler/probe boundary | 30% | Scheduler uses uptime while probe stores `Date`; forward/backward wall jumps directly change eligibility | 95% |
| H2: pending retry state is stale or non-atomic | 35% | Locking, reset hygiene and absolute-deadline tests pass under a continuous clock | 3% |
| H3: stable scheduler deadline math is still wrong | 35% | Off-grid, overrun and relative-hint regressions pass; only wall discontinuity distinguishes the failure | 2% |

Confidence is above 90% because the Review counterexamples follow directly from `Date.timeIntervalSince` while monotonic scheduler time remains unchanged.

## 1. Root Cause Category

- **Category**: E - Implicit Assumption; B - Cross-Layer Contract; D - Test Coverage Gap.
- **Specific Cause**: scheduler cadence is expressed in monotonic uptime, but BubbleVisibility stores capture and retry instants as wall-clock `Date`. Both expose interval arithmetic, so the implementation and shared fake scalar concealed the incompatible clock domains.

## 2. Why Fixes Failed

1. **Absolute retry deadline fix**: correctly removed duplicated relative waiting, but preserved `Date` from the pre-existing probe and therefore fixed only arithmetic shape, not clock semantics.
2. **Unified fake-clock integration test**: drove scheduler and probe from one continuously increasing scalar, so it could not distinguish monotonic time from a wall clock that jumps.
3. **Review focus**: earlier rounds concentrated on phase, work duration and source liveness; the boundary map stopped at numeric timestamp values instead of identifying each clock source.

## 4. Systematic Expansion

- **Similar Issues**: Follower already uses `systemUptime`; follow scheduler and BubbleVisibility are the only cadence boundary in this task that must be unified. Calendar/data refresh timestamps are outside scope unless they participate in elapsed-time scheduling.
- **Design Improvement**: the production data flow must be `systemUptime → tick/capture instant → absolute retry instant → remaining delay`, with no wall-clock conversion.
- **Process Improvement**: cadence integration tests need two independent controls—monotonic elapsed time and irrelevant wall time—rather than a single generic `now` scalar.
- **Knowledge Gap**: identical `TimeInterval`-shaped values do not imply compatible epochs or discontinuity behavior.
