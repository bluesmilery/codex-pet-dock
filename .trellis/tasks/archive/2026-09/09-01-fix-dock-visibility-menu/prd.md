# 修复底座消失与菜单误跟随

## Delivery Path

L2（应用运行时窗口识别、ScreenCaptureKit 像素探测与 AppKit 布局行为）。

## Goal

在当前 Codex 宿主窗口结构下，PetDock 必须持续识别屏幕上的真实宠物并把底座放在宠物下方；Codex 右键菜单等与宠物无关的临时窗口不得触发底座出现、迁移或重新锚定。

## Background and Confirmed Facts

- 用户现场截图证明两个相邻症状：正常显示宠物时底座缺失；打开 Codex 会话右键菜单后，底座错误出现在菜单下方。
- 本机正在运行的安装包与 `v0.5.0` 发布候选一致。该版本的产品源码没有包含已停放在 `feature/pet-window-adaptation` 的容器宠物回退通道，因此宿主不再暴露独立 Mascot 窗口时，正常状态下没有可用宠物锚点。
- 当前 `PetTracker.selectPet` 在主 Mascot 缺失时仍会从小型非主窗口中做几何回退。右键菜单出现后存在被宿主临时窗口误触发的可能；真实触发窗口种类仍需同一候选的脱敏运行时证据确认，不能仅凭截图猜测具体 WID、title 或 bounds。
- 已停放的容器通道通过 ScreenCaptureKit 在内存中计算 alpha bbox 来恢复窗内宠物位置，保持 1 秒稳定捕获节奏与既有 CPU 档位；它尚未合入 `dev` / `v0.5.0`。
- 容器通道现有语义把捕获到的完整不透明 bbox 当作宠物及其附属内容的整体锚点。它没有显式定义如何排除同一宿主容器中的无关上下文菜单，因此本轮不能只把旧 feature 机械合入后宣称两个症状都已解决。

## Requirements

- R1：保留独立 Mascot 窗口作为最高优先级主通道；已有宠物窗口、Composition Surface、气泡和控制按钮行为不得回归。
- R2：在独立 Mascot 缺失但宠物仍绘制于宿主透明容器时，使用容器回退通道恢复真实宠物矩形，并通过既有 `Follower → FollowTickPlan → DockPanel` 状态机显示底座，不另起平行 UI 状态机。
- R3：Codex 右键菜单、子菜单和其他与宠物无关的临时窗口不得被 `selectPet` 当成宠物，也不得扩张容器通道的宠物内容锚点。
- R4：菜单关闭后不得残留错误锚点、可见性或滞回状态；底座继续以真实宠物为唯一位置来源。
- R5：不得通过提高全窗捕获频率掩盖问题。保持既有 1 秒稳定捕获档位、移动期快速档位及已接受的稳定态 CPU 边界；新增分类/分割不得引入持续高频捕获。
- R6：像素处理继续只在内存中使用 alpha 统计或匿名几何，不 OCR、不保存图像、不记录颜色、文字、WID/PID、标题或绝对坐标。
- R7：修改必须最小化，并从现有 `feature/pet-window-adaptation` 的已停放功能基线继续；完成后仍按项目规则停放到同一 feature，后续由独立集成任务串行合入 `dev`。

## Acceptance Criteria

- [ ] AC1 基线证据：在批准基线上重放两条症状对应的生产链测试；底座缺失与菜单误触发分别记录为基线失败或覆盖缺口，不为制造红测而改产品代码。
- [ ] AC2 无菜单：宿主仅提供透明容器内宠物时，捕获结果经过真实容器 probe、callback / scheduler、完整 follow tick，最终 `DockPanel.frame` 位于真实宠物下方且面板可见。
- [ ] AC3 菜单打开：注入与真机脱敏 outcome 等价的临时菜单扰动后，生产组合最终 `DockPanel.frame` 继续稳定位于真实宠物下方，面板保持可见且不移动到菜单下方。
- [ ] AC4 菜单关闭：同一生产组合清除临时菜单扰动后无残留错误滞回，底座继续或恢复锚定真实宠物，且不会出现额外跳变。
- [ ] AC5 回归保护：Mascot 主通道、宠物自身气泡/控制按钮、容器内宠物真实移动、跨屏与隐藏/重现语义保持现有合同；无关临时菜单的排除不能误删宠物附属内容。
- [ ] AC6 自动门禁：`swift build -c release` 零 warning，`make test` 全绿，Review 对冻结完整 SHA 的 P0/P1/P2 全部清零。
- [ ] AC7 真机 QA：同一冻结 SHA 在亮屏、已授权 ScreenCaptureKit/TCC 环境中重放“正常宠物、打开右键菜单、关闭菜单”，同时取得脱敏生产 outcome 与 UI 结果；自动测试、静态 Review、真机 QA 分开报告。
- [ ] AC8 性能与体验：容器通道活跃时至少 60 秒稳定态 CPU 不突破既有已接受档位；底座无持续抖动，宠物移动与菜单开合过程中无错误长距离滑移。

## Out of Scope

- 不修改 Codex 应用或 Chrome Profile，不使用私有 CGS / SPI。
- 不新增设置项，不改变底座内容、主题或数据刷新逻辑。
- 本开发任务以获得 accepted feature SHA 为终点；按项目分支规则，合入 `dev`、重建发布候选和发布操作由后续专门集成 / 发布任务处理。

## Key Decisions

- 用户确认：右键菜单打开期间，底座继续稳定显示在真实宠物下方；不得为了规避误绑定而临时隐藏底座。
- 用户指定：本会话后续所有子 Agent 使用 `zhipu-bigmodel-coding/glm-5.3`、`max`；需要电脑操作时使用 `kimi-cu`，不得静默替换模型或操作通道。
- 两个症状属于同一宠物来源选择链路，作为一个可独立验收的 L2 deliverable 处理，不拆 parent / child task。
- 先在现有 feature 基线上区分“独立临时窗口误选”与“菜单像素进入容器”两种真实触发；只实施证据支持的最小修复。若证据指向容器内像素分割，必须回到规划更新设计，不在实现阶段静默扩张方案。
